# Security

## Reporting a problem

Email the maintainer listed on the GitHub repository with what you found and how to reproduce it. Please do not open a public issue for a vulnerability. We aim to reply within two working days.

## What we protect

Records about children's sport: which player (a label and a shirt number) played, trained and was observed, in which club. The main risk is one club, or the public, reading or changing another club's records.

## Practices

- Secrets never enter the repository or the browser. The only keys in the client are public by design.
- Every change to the schema is a migration, reviewed like code and applied to an empty database in CI.
- Dependencies are installed from the lockfile; `--force` and `--legacy-peer-deps` are not used.
- Errors shown to users come from a fixed list of messages; raw server text is never displayed.

## Known limits

- The anonymous demo is rate-limited by the platform but has no CAPTCHA.
- Email one-time codes depend on the email provider's delivery limits.
- There has been no external penetration test.
